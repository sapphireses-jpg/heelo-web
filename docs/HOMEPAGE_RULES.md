# CLAUDE.md — [서비스명] 안내 홈페이지

## 이 저장소는
[서비스명] 앱의 **안내용 정적 홈페이지**입니다. 서비스 소개, 앱 다운로드, 고객센터, 계정 삭제 안내, 약관 3종(버전별), 사업자 정보를 보여 줍니다.
로그인, 입력 폼, 서버·DB 연결 같은 **기능은 만들지 않습니다.** 문의와 삭제 요청은 메일 링크(mailto)로만 받습니다.

- 문안 기준: `CONTENT.md`. 문안을 임의로 늘리거나, 기능·약속을 새로 적지 않습니다. 바꿔야 하면 오너에게 먼저 묻습니다.
- 호스팅: GitHub Pages. 임시 주소는 github.io이고, 도메인은 서비스명 확정 뒤 연결합니다. 저장소 이름이 `<계정>.github.io`가 아니면 주소에 `/<저장소 이름>/`이 붙으므로, base 값은 설정 한 곳에서 관리하고 모든 내부 링크가 base를 따르게 합니다. 도메인 연결 뒤에도 base 아래 경로(`/support/`, `/account/delete/` 등)는 바뀌지 않아야 합니다.
- 언어·화면: 한국어, 모바일 우선.

## 기술
- Astro(정적 출력), UI 프레임워크 없음. **브라우저 자바스크립트 0**을 기본으로 합니다. 꼭 필요하면 오너에게 먼저 묻습니다.
- 배포: GitHub Actions → GitHub Pages. 매일 00:05(KST, cron `5 15 * * *`)에 다시 빌드해 약관 시행일이 지나면 현재본이 자동으로 바뀌게 합니다.

## 꼭 지킬 것
1. **외부 요청 0.** 분석·추적 도구, 쿠키, 외부 글꼴 CDN(구글 폰트 포함), 외부 스크립트, 외부 이미지, 지도·영상 임베드를 쓰지 않습니다. 글꼴은 `public/fonts/`에 직접 두고(woff2, 한글은 서브셋), 이미지도 저장소 안에 둡니다. 외부로 가는 것은 사람이 누르는 링크(`<a href>`, `mailto:`)뿐입니다.
2. **설정값은 한 곳에서.** 서비스명, 문의 메일, 답변 기간, 가격, 스토어 링크, `launchStatus`(soon/live), 사업자 정보는 `src/config/`에만 둡니다. 페이지에 직접 쓰지 않습니다. 서비스명이 바뀌면 설정 한 줄로 끝나야 합니다.
3. **약관 버전 규칙.**
   - 파일: `src/content/legal/<문서>/<버전>.md` (문서: terms, privacy, location / 버전: v1.0, v1.1 …)
   - 머리 정보: `title`, `version`, `announced`(공고일), `effective`(시행일), `summary`(주요 변경), `status`(draft | published)
   - 주소: 현재본 `/legal/<문서>/`, 버전별 고정 주소 `/legal/<문서>/<버전>/`
   - 현재본 = `published` 중 시행일이 오늘(KST) 이하인 가장 최신 버전. 시행일이 미래인 버전은 "시행 예정"으로 안내합니다. 공고일과 시행일이 같은 개정도 지원합니다.
   - 변경 이력 표는 머리 정보로 자동 생성합니다.
   - **한 번 `published`로 배포된 버전 파일은 수정·삭제하지 않습니다.** 고칠 내용이 있으면 새 버전을 만듭니다.
   - `draft` 파일은 배포 결과물에 넣지 않습니다(로컬 미리 보기만).
   - 약관 원문에 Mermaid 흐름도가 있으면 번호 목록 문장으로 바꾸거나 빌드 때 SVG로 만들어 넣습니다. 화면에서 스크립트로 그리지 않습니다.
   - 임시 초안(status: preview): 정식 버전이 없는 문서에 한해, 앱 테스트용 초안을 현재본 주소(/legal/<문서>/)에 보여 줄 수 있습니다. 파일은 src/content/legal/<문서>/preview.md이고, 머리 정보에 source(원문 경로, 원문 파일 SHA-256, 가져온 날짜)를 적습니다. 원문의 「법률 검토 쟁점」 절은 빼고, [검토: …]는 (검토 중), [개발 확인: …]·[DPA 확인…]는 (확인 중)으로 바꿔 게시합니다. 본문 위에 「초안·테스트용」 안내를 띄우고 noindex를 붙이며, 버전 목록·변경 이력·버전별 주소에는 넣지 않습니다. 버전 불변 검사 대상이 아닙니다. 같은 문서에 published 버전이 생기면 preview는 지웁니다.
   - 베타 적용판: 비공개 베타 기간에 적용하는 문서는 src/content/legal/beta/<문서>.md, 주소는 /legal/beta/<문서>/입니다(앱 링크). 원문은 앱 저장소 docs/legal/beta/<문서>-beta.md이고, 첫 줄 주석만 빼고 그대로 가져옵니다. 머리 정보는 title, version(예: v0.9), status(draft | published), source(원문 경로, SHA-256, 가져온 날짜)이며, published로 바꿀 때 announced·effective를 적습니다. 본문 위에 베타 안내를 띄웁니다. published 파일은 검토 흔적 검사(자리표시 포함)와 버전 불변 검사를 그대로 받습니다.
4. **개인정보 처리방침 링크**는 하단에서 굵게 표시해 다른 링크와 구별합니다.
5. **스토어 배지**는 Apple·Google 공식 이미지를 변형 없이 씁니다. `launchStatus: soon`이면 배지와 링크 대신 CONTENT.md의 출시 준비 문장을 보여 줍니다.
6. **기록 보존.** 랜딩 문구는 표시·광고 기록이라 Git 기록을 지우지 않습니다. force push, 기록 재작성 금지.
7. **데이터 접근 금지.** 이 저장소 작업에서 Supabase(운영·개발 모두)나 앱 데이터베이스에 접속하지 않습니다. 비밀값을 저장소에 넣지 않습니다(이 사이트에는 필요한 비밀값이 없습니다).
8. 약관과 관련된 홈페이지 문안(탈퇴, 보관, 구독, 위치, 가족 등)은 앱 저장소 docs/legal을 원본으로 삼습니다. 원본이 바뀌면 문안을 대조해 불일치를 보고합니다.

## 자동 검사 (CI에서 실패 처리)
- **외부 리소스 검사**: 빌드 결과(`dist/`)에서 `src`, `<link href>`, CSS `url()`·`@import` 등 리소스를 불러오는 곳에 외부 주소가 있으면 실패. `<a href>`와 `mailto:`는 허용.
- **검토 흔적 검사**: `published` 약관 파일에 `[검토`, `[개발 확인`, `[DPA`, `검토용 주석`, `법률 검토 쟁점`이 남아 있으면 실패.
- **출시 자리표시 검사**: `src/config`의 `launchReady: true`일 때, 결과물에 `[서비스명]` 같은 대괄호 자리표시가 하나라도 남아 있으면 실패. 출시 전(`false`)에는 경고만.
- **버전 불변 검사**: 이전 커밋에서 `published`였던 약관 파일의 내용이 바뀌거나 삭제되면 실패.

## 디자인
- 브랜드 색·글꼴은 오너의 디자인 가이드가 오면 적용합니다. 그 전에는 CSS 변수(색·글꼴·간격 토큰)만 정의하고 중립값을 넣어, 가이드가 오면 토큰만 바꾸면 되게 합니다.
- 키보드 포커스 표시, 충분한 명도 대비, `prefers-reduced-motion` 존중. 긴 표는 가로 스크롤 상자 안에 둡니다.
- 지도 스크린샷을 쓰면 이미지 안이나 바로 아래에 "© Mapbox © OpenStreetMap"을 표기합니다.
